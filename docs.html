🔌 Current FreeScout Integration

Note: Temporary implementation due to the absence of the API & Webhooks module. Once the module is installed, this will be replaced by a direct REST API integration using the FreeScout API.

The current integration works by replaying the same HTTP requests a browser makes when an admin creates a ticket manually in FreeScout:

  1. GET /login — extract CSRF token from the login page HTML
  2. POST /login — authenticate as admin, obtain session cookie
  3. GET /mailbox/{id}/new-ticket — fetch a fresh CSRF token
  4. POST /conversation/ajax — create the ticket (action=send_reply + is_create=1)

Current tickets are created in the default Unassigned mailbox. Automatic routing to dedicated folders/agents will be implemented once the FreeScout API module is available.

⚠️ Known Limitations

Fragile FreeScout integration: The current implementation depends on FreeScout's HTML page structure to extract CSRF tokens. Any significant change to the FreeScout interface may require updating the HTTP session workflow. This will be resolved once the API & Webhooks module is available.
CORS policy: allow_origins=["*"] is acceptable for local development. Must be restricted to the production domain before deployment.
OLLAMA_API_KEY required: FastAPI refuses to start if the key is missing (.env). This is intentional — the classifier cannot function without it.
