🤖 AI Ticket Triage Service

Project reference — architecture, features delivered, and technical decisions

📋 Overview

A Python service that sits alongside FreeScout and automatically classifies every incoming support ticket by category, priority, and sentiment using an LLM. Low-confidence tickets are routed to a dedicated Needs Review queue. A suggested reply draft is generated for every ticket based on the customer's actual message.

Built entirely on open-source tools. Uses mikeyperes/freescout-api-webhooks — a free, open-source FreeScout module. No paid modules required.

🔌 Open-Source FreeScout Module

This project uses mikeyperes/freescout-api-webhooks, a free open-source module — not the paid official FreeScout module. It provides identical functionality at zero cost.

The module is cloned automatically by the module-init Docker container on first startup. No manual installation needed.

How the sidebar works

The Python service writes classification results to conversation.meta via a single PUT call. The PHP ServiceProvider in the module reads those meta fields and renders the sidebar panel directly inside FreeScout. No separate note or thread is posted into the conversation.

🔁 Idempotency & Auto-Poll

Idempotency

Every processed conversation ID is stored in a MySQL triage_processed table using INSERT IGNORE. If FreeScout retries a webhook or the poller runs again, the ticket is silently skipped — never classified twice.

Auto-poll

The service starts an asyncio background task on startup that polls FreeScout every POLL_INTERVAL_SECONDS (default 30s). No manual command needed. Tickets are classified within 30 seconds of arriving in FreeScout.

Webhook (instant)

When TRIAGE_WEBHOOK_URL is set in the Docker environment, the PHP module fires a POST /webhook immediately when a conversation is created — no waiting for the poll cycle.

✏️ Suggested Reply

Every triage result includes a reply draft generated by the LLM. The reply is based on the customer's actual message and subject — not on the category label.

  • Answers what the customer actually asked or reported
  • Never invents facts not present in the message
  • Never assumes a problem from the category alone (billing ≠ billing problem)
  • Never makes unsupported promises (refunds, deadlines, team assignments)
  • Matches the language of the customer's message

The draft appears in the FreeScout sidebar under Suggested Reply — the agent can copy it directly into the reply box.
